# 開発ワークフロー

> プロジェクトの標準的な開発フローを定義します。
> Gemini CLI を各フェーズでどのように活用するかも記載しています。

## フロー概要

```mermaid
graph LR
    A[1. 計画] --> B[2. 設計]
    B --> C[3. 実装]
    C --> D[4. テスト]
    D --> E[5. レビュー]
    E --> F[6. マージ]
    F --> G[7. デプロイ]
```

---

## 1. 計画（Planning）

### 目的
タスクの要件を明確にし、作業範囲を定義する。

### 手順
1. Issue / チケットの内容を確認する
2. 受け入れ条件（Acceptance Criteria）を明確にする
3. 作業の規模を見積もる
4. 作業ブランチを作成する

### Gemini CLI の活用
```
このIssueの内容を分析して、タスクを分割してください: {Issue URL}
```

---

## 2. 設計（Design）

### 目的
実装方針を決定し、影響範囲を把握する。

### 手順
1. 既存のコードベースを調査する
2. 設計案を作成する（必要に応じてドキュメント化）
3. チームに設計レビューを依頼する

### Gemini CLI の活用
```
以下の機能を実装するための設計案を作成してください。
まずコードベースを調査し、既存のパターンに合わせた設計を提案してください。
```

---

## 3. 実装（Implementation）

### 目的
設計に基づいてコードを実装する。

### 手順
1. テストを先に書く（TDD推奨）
2. 最小限の実装から始める
3. こまめにコミットする

### Gemini CLI の活用
```
以下の設計に基づいてコードを実装してください。
TDDのアプローチで進め、テストを先に書いてください。
```

---

## 4. テスト（Testing）

### 目的
実装したコードの品質を検証する。

### 手順
1. ユニットテストを実行する
2. 統合テストを実行する（該当する場合）
3. テストカバレッジを確認する

### Gemini CLI の活用
```
テストを実行し、カバレッジを確認してください。
不足しているテストケースがあれば追加してください。
```

---

## 5. レビュー（Review）

### 目的
コードの品質を第三者の視点で確認する。

### 手順
1. セルフレビューを行う
2. Gemini CLI でコードレビューを実施する
3. チームメンバーにレビューを依頼する
4. 指摘事項を修正する

### Gemini CLI の活用
```
@code-reviewer 変更されたファイルをレビューしてください
```

---

## 6. マージ（Merge）

### 手順
1. すべてのテストがパスしていることを確認
2. レビューの承認を得る
3. マージする（Squash Merge推奨）

---

## 7. デプロイ（Deploy）

### 手順
1. ステージング環境にデプロイ
2. 動作確認
3. 本番環境にデプロイ
4. 本番環境での動作確認
