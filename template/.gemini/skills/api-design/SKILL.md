# API設計ワークフロー スキル

RESTful API を設計・実装する際の標準的な手順を定義します。
一貫性のある API 設計を実現し、ドキュメントとテストを同時に整備します。

## 前提条件

- API フレームワークがプロジェクトに導入されていること
- データベース（またはデータソース）が準備されていること

## 手順

### ステップ 1: 要件定義 📋

1. API のユースケースを一覧化する
2. 必要なリソース（エンティティ）を洗い出す
3. リソース間の関係を定義する

```markdown
## リソース一覧
| リソース | 説明 | 主要な操作 |
|---------|------|-----------|
| /users | ユーザー | CRUD |
| /posts | 投稿 | CRUD, 検索 |
```

### ステップ 2: エンドポイント設計 🔗

1. URL パスを設計する（リソースベース、複数形）
2. HTTP メソッドを割り当てる
3. リクエスト/レスポンスのスキーマを定義する

```markdown
## エンドポイント設計

### /api/v1/users

| メソッド | パス | 説明 | 認証 |
|---------|------|------|------|
| GET | /api/v1/users | ユーザー一覧取得 | 🔓 |
| GET | /api/v1/users/:id | ユーザー詳細取得 | 🔓 |
| POST | /api/v1/users | ユーザー作成 | 🔒 |
| PUT | /api/v1/users/:id | ユーザー更新 | 🔒 |
| DELETE | /api/v1/users/:id | ユーザー削除 | 🔒 |
```

### ステップ 3: スキーマ定義 📐

1. リクエストボディのスキーマを定義する
2. レスポンスボディのスキーマを定義する
3. エラーレスポンスの統一フォーマットを定義する

#### エラーレスポンス統一フォーマット
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message",
    "details": []
  }
}
```

#### HTTPステータスコード規約
| コード | 用途 |
|--------|------|
| 200 | 成功（データ返却あり） |
| 201 | 作成成功 |
| 204 | 成功（データ返却なし） |
| 400 | バリデーションエラー |
| 401 | 認証エラー |
| 403 | 認可エラー |
| 404 | リソース未発見 |
| 409 | コンフリクト |
| 422 | 処理不可 |
| 500 | サーバーエラー |

### ステップ 4: 実装 💻

1. ルーティングを実装する
2. バリデーションを実装する
3. ビジネスロジックを実装する
4. エラーハンドリングを実装する

### ステップ 5: テスト・ドキュメント 📝

1. 各エンドポイントのテストを作成する
2. API ドキュメントを生成する（OpenAPI / Swagger）
3. サンプルリクエストを用意する
