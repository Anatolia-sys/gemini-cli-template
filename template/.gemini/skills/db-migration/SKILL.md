# データベースマイグレーション スキル

データベーススキーマの変更を安全に計画・実行するための手順を定義します。
データ損失を防ぎ、ロールバック可能な変更を実現します。

## 前提条件

- マイグレーションツールが導入されていること（例: Prisma, Alembic, Flyway, knex）
- データベースへの接続が可能であること
- バックアップの取得手段があること

## 手順

### ステップ 1: 変更の計画 📋

1. スキーマ変更の要件を明確にする
2. 影響を受けるテーブル・カラムを特定する
3. 既存データへの影響を分析する
4. ダウンタイムの有無を判断する

```markdown
## マイグレーション計画

| 項目 | 内容 |
|------|------|
| 変更概要 | ... |
| 影響テーブル | ... |
| 既存データへの影響 | あり / なし |
| ダウンタイム | 必要 / 不要 |
| ロールバック方法 | ... |
```

### ステップ 2: マイグレーションファイル作成 📝

1. マイグレーションファイルを生成する
2. UP（適用）の処理を記述する
3. DOWN（ロールバック）の処理を記述する

#### 安全なマイグレーションの原則

| ✅ 安全 | ❌ 危険 |
|---------|---------|
| カラムの追加（NULL許容） | カラムの削除 |
| テーブルの追加 | テーブルの削除 |
| インデックスの追加 | カラム型の変更 |
| デフォルト値の追加 | NOT NULL制約の追加（既存データあり） |

#### 破壊的変更の安全な実施手順

カラム削除の場合：
1. 🟢 アプリケーションコードからカラムの参照を削除
2. 🟢 デプロイ・動作確認
3. 🟡 マイグレーションでカラムを削除
4. 🟢 デプロイ

### ステップ 3: テスト環境での検証 🧪

1. テスト環境でマイグレーションを実行する
2. アプリケーションの動作を確認する
3. ロールバック（DOWN）を実行し、正常に戻ることを確認する

```bash
# マイグレーション実行例
npx prisma migrate dev        # Prisma
alembic upgrade head          # Alembic
npx knex migrate:latest       # Knex
flyway migrate                # Flyway

# ロールバック例
npx prisma migrate reset      # Prisma
alembic downgrade -1          # Alembic
npx knex migrate:rollback     # Knex
flyway undo                   # Flyway
```

### ステップ 4: 本番適用 🚀

1. データベースのバックアップを取得する
2. メンテナンスウィンドウを設定する（必要な場合）
3. マイグレーションを実行する
4. 動作確認を行う
5. 問題があればロールバックする
